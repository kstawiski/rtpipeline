# The course contract must be the only treatment-selection authority

The repaired pipeline treats the organize stage as the sole authority for per-course treatment selection. This rule prevents copied but undelivered plans from entering dose-volume histograms and dose-response analyses without changing the organizer's recorded dose.

A read-only reconstruction found disagreement between the legacy organizer and DVH plan membership in 2 of 4 Kopernik courses with both prescription and DVH data. The fixed resolver reproduced organizer membership in all 4 courses when replayed against their DICOM headers.

The planned dose grid explicitly defines what it represents. Delivered exposure remains `delivered_dose_gy`. Dose-response analyses should use delivered dose, whereas treatment-intent and plan-quality analyses may use prescribed dose and the labelled planned grid.

A target-bearing, plan-only course is a valid retained course rather than a failed course. When the organize stage selects a plan without an authoritative RTDOSE object, the contract preserves plan membership, sets the dose grid to null, and labels DVH metrics as not computed. The DVH stage removes stale metrics, emits no workbook, and records this decision in `dvh_qc.json`. The command-line interface treats this validated outcome as successful, allowing the workflow to publish an `ok` DVH sentinel. Aggregation then retains the completed course without inventing dose rows.

## The defect

The organizer linked plans, doses, treatment records, structures, and planning images. It then copied every candidate RT object into the course directory. Downstream stages scanned that directory and made a second selection.

The course directory was therefore a transport container, not a treatment-membership record. Filenames, directory order, and readable bystander objects could replace the organizer's reference-driven decision.

The legacy `case_metadata.json` file recorded selected source UIDs but could leave `rp_path`, `rd_path`, and `rs_path` empty. Downstream stages therefore lacked the complete contract needed to follow the organizer's decision.

## The authoritative contract

The organizer writes one versioned `course_contract` object inside `metadata/case_metadata.json` under the authority `organize`. Patient and course identifiers must match the containing directory.

The contract carries the following decisions.

| Concept | Required record |
|---|---|
| Selected plans | Ordered RTPLAN SOP Instance UIDs and course-relative paths |
| Selected doses | Ordered RTDOSE SOP Instance UIDs, paths, `DoseSummationType`, and referenced plan UIDs |
| Structures | The authoritative RTSTRUCT SOP Instance UID and path |
| Planning CT | CT Series Instance UID, selected DICOM directory, NIfTI path, reference status, and referenced series UIDs |
| NIfTI provenance | Sidecar path, CT-series identity, source-instance hash, geometry and orientation metadata, and NIfTI content hash |
| Delivery | Per-plan evidence, selected-for-grid status, delivered record and fraction counts, dates, zero-record status, and copied RTRECORD paths |
| Dose | Prescribed dose, delivered dose, delivery status, calculation method, and `delivered_dose_gy` as the dose-response field |
| Derived plan artifact | Path, SOP UID, source plan UID set, and derivation semantics |
| Dose grid | Path, SOP UID, summation type, source plan UIDs, source dose UIDs, source summation types, and grid semantics |
| Dose QC | Pass or fail, configured maximum total dose, and reasons |
| DVH decision | Status, reason code, dose-record status, metric status, and output artifact |

When contracted artifacts exist, the organizer also populates compatible top-level `rp_path`, `rd_path`, and `rs_path` fields. Downstream selection stages do not use these fields as a second authority.

## Planned and delivered dose

A plan with zero RTRECORD delivery records is considered undelivered. When treatment evidence exists for the patient, that plan contributes neither delivered dose nor a dose grid claiming to represent delivered treatment.

When no RTRECORD objects exist, delivery status is unknown rather than zero. The contract records `no_records_at_all` and does not invent delivered dose values. A planned grid remains valid only when its metadata explicitly states that it represents the selected plan set rather than delivered exposure.

When a selected plan has no resolvable RTDOSE object, the contract sets `dose_grid` to null. Its DVH decision records `status` as `"not_computed"`, `metrics_status` as `"not_computed"`, and `reason_code` as `"plan_only_no_authoritative_dose_grid"`. When no RTRECORD object exists, setting `dose_record_status` to `"delivery_unknown_no_rtrecord"` states the evidence ceiling without asserting that no dose was delivered. The missing RTDOSE remains a separate computational reason for not producing metrics. The DVH stage copies this validated decision into `metadata/dvh_qc.json`, removes stale metrics, and emits no workbook.

A genuine sequential boost remains additive when delivery evidence exists for both phases. A plan is not summed simply because its file was copied into the course directory.

`PLAN` and `PLAN_SUM` doses are distinct from beam-level doses. The organizer prefers a plan-level total dose grid. It uses beam-level components only for a single selected plan when no plan-level total is available. The contract rejects any mixture of plan-level and beam-level sources.

Prescribed dose represents treatment intent, whereas the planned dose grid represents the selected plan set. Delivered dose represents physical exposure supported by RTRECORD evidence. Dose-response analyses must use `delivered_dose_gy` and retain the associated delivery status.

## Fail-closed behavior

Every downstream course entry point loads the same contract before resolving treatment objects. Any missing, malformed, incomplete, path-escaping, unreadable, role-swapped, UID-mismatched, or stale contract raises `CourseContractError`. The validator also requires the complete DVH decision to match the canonical decision derived from selected plan membership, selected dose membership, and delivery status. No entry point falls back to scanning copied candidate files or accepting stale DVH claims.

Validation verifies the SOP Instance UID, Modality, and SOP Class for every selected plan, selected dose, authoritative RTSTRUCT, derived plan artifact, and dose grid. It verifies dose summation types and dose-to-plan references. It also verifies the selected CT series, source-instance hash, NIfTI sidecar identity, geometry and orientation metadata, and NIfTI content hash.

Delivery claims require auditable RTRECORD paths when fraction counts are non-zero. Each record must be a valid RTRECORD object, reference the declared plan, and reproduce the declared record count, fraction count, and treatment dates. Zero-record entries are explicit and remain visible for excluded plans.

A valid contract lacking an authoritative dose grid differs fundamentally from a missing or stale contract. The function `require_dvh_artifacts()` therefore returns the authoritative plan with a null dose grid for plan-only courses. The stricter `require_computable_dvh_artifacts()` remains available for dose-based calculations. The DVH stage records an explicit skip-QC result, removes stale outputs, and emits no workbook. The command-line interface confirms that the contract and QC record agree, then returns success with a structured `not_computed` outcome. This design preserves the organizer's plan-only decision without treating it as data corruption or pipeline failure.

A failing dose-QC verdict strictly binds downstream behavior. The DVH stage evaluates this verdict before cache reuse, invalidates stale workbooks, and records the failure. The command-line interface returns a stage failure for this outcome. Aggregation rejects missing, stale, unreadable, malformed, or dose-QC-failing courses. However, aggregation does not reject a validated plan-only course. Instead, aggregation requires its skip-QC record, contributes no DVH rows, and logs `plan_only_no_authoritative_dose_grid` with status `not_computed` in the campaign attrition table.

## Unified definitions

Dose classification is implemented solely during the organize stage and serialized in the contract. The DVH stage contains no independent treatment-dose classifier or plan-membership selector.

`PipelineConfig.max_total_dose_gy` is the single dose-plausibility threshold. Temporary all-series contracts use this same default constant. The DVH stage verifies that the configured threshold matches the contract rather than defining a local threshold.

`rt_details.DEFAULT_ROI_FAMILY_NAMES` provides the shared region-of-interest (ROI) family definitions. Target recognition uses its GTV, CTV, and PTV subset. Radiomics robustness imports this same definition rather than maintaining an independent list of GTV, CTV, PTV, BLADDER, and RECTUM structures.

## Verification and remaining boundary

Regression tests cover copied candidate supersets, selected membership, zero-delivery plans, undelivered sequential phases, and delivered sequential phases. They also verify PLAN and BEAM dose separation, missing and stale contracts, role swaps, delivery evidence, derived-artifact binding, planning CT and NIfTI provenance, plan-only CLI success, dose-QC CLI failure, all-series backend scope, structure provenance, aggregation, and planning-CT consumption.

The two serializer branches now have paired organize-to-DVH round trips using contracts written by organize itself. The plan-only branch uses a synthetic target-bearing course with one RTPLAN and no RTDOSE. It asserts that organize's non-empty plan membership survives DVH, selected doses stay empty, no workbook is emitted, and the typed not-computed outcome names the missing authoritative dose grid.

The dose-bearing branch uses synthetic valid RTPLAN, plan-level RTDOSE pixels, RTSTRUCT contours, planning CT headers, and RTRECORD evidence. Organize's real record index discovers the synthetic RTRECORD. The test asserts non-empty selected plan and dose membership, populated dose-grid metadata, `partially_delivered` status, one record and one delivered fraction on 20240102, an auditable RTRECORD path, and 2.75 Gy delivered dose. DVH reads those selections and delivery fields from the organize-written contract, computes metrics, and writes `dvh_metrics.xlsx`. The workbook and `dvh_qc.json` retain the same selected plan UIDs, `partially_delivered` status, and 2.75 Gy delivered dose. The emitted DVH decision reports `metrics_status` as `computed`, and its output path exists. The contract bytes, dose-grid semantics, and dose-QC threshold remain unchanged. Both round trips use synthesized DICOM and require no patient DICOM.

The all-series test loads the materializer's temporary contract and confirms one `AutoRTS_total` source for the copied RTSTRUCT. Serial radiomics records that source. The parallel fallback forwards the restricted opt-in to the conda environment, while direct course-level calls remain rejected.

The full local test suite completed with 954 passed and 2 skipped tests under Python 3.14. The 89 focused repair tests also passed under the minimum supported Python 3.10. Python compilation and `git diff --check` completed without errors.

The real-course comparison confirms membership control without recalculating new cohort DVH values. A subsequent governed rebuild should regenerate downstream workbooks from the repaired contracts, preserve contract provenance, and exclude or flag courses with failing dose QC.

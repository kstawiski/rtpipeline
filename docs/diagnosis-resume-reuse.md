# Resume should reuse current content

The clinical processing question is whether a resumed radiotherapy course requires a new segmentation model run. The answer must depend on the current planning computed tomography (CT) scan and its derived artefacts, not on whether a pipeline stage marker exists. This distinction matters because a missing automatic radiotherapy structure set (`RS_auto`) can coexist with a complete, valid bank of TotalSegmentator anatomical masks.

After the automatic radiotherapy structure set (RTSTRUCT) geometry fix, 121 DFCI courses and 1 Kopernik course reportedly contained all 117 TotalSegmentator masks but lacked `RS_auto`. The reported inventory was 16,424 DFCI mask files and 234 Kopernik mask files. The missing derived structure set did not indicate that the underlying masks were missing or invalid [1].

Clearing `.segmentation_done` to rebuild `RS_auto` triggered an unnecessary rerun of TotalSegmentator. Recent courses on server s1 generated 55 model-run log lines and required 322 to 494 seconds per course even though 117 masks were already present. At roughly seven minutes per course, repeating the model across 230 DFCI courses would take about 27 hours. Repeating it across 122 Kopernik courses would take about 14 hours. These figures represent reported cohort calculations rather than a new campaign-time measurement [1].

The defect arose from using a stage-level completion marker to make an artefact-level decision. The sentinel file `.segmentation_done` records only that a processing stage finished. It does not prove that each output exists, is readable, is current, or corresponds to the inputs selected for the active course. The sentinel remains a workflow marker rather than evidence that an expensive model rerun is required [1, 2].

The revised segmentation decision starts with the authoritative course contract. The contract identifies the planning CT series and its NIfTI image volume. To permit reuse, a mask manifest must identify that exact series, match the hash of the current planning NIfTI, and list a complete set of readable masks whose physical geometry matches the current planning scan. If any check of identity, inventory, readability, geometry, or freshness is uncertain, the model runs again. This approach is deliberately fail-closed because reusing a mask from another planning CT is more harmful than recomputing a valid mask [2].

Legacy mask banks receive only a narrow upgrade path. The sidecar metadata for series identity and NIfTI hash must match the current planning CT and NIfTI. When a sidecar contains the NIfTI content-generation timestamp, the mask manifest timestamp must be later than that generation time. Older sidecars do not use their metadata write time as evidence. Instead, they require filesystem ordering showing that the mask manifest was written after the current NIfTI. Any uncheckable timestamp ordering rejects reuse [2].

A refreshed metadata sidecar therefore does not invalidate legacy masks merely because its own `generated_at` field is newer than the mask manifest. When an existing NIfTI is reused, its sidecar preserves the original generation timestamp. A newly converted NIfTI receives a distinct `nifti_generated_at` timestamp that describes content generation rather than a later metadata refresh [2].

The pipeline stage now separates deep-learning model outputs from derived structures. A complete, current mask set is reused without invoking TotalSegmentator. If the model DICOM RTSTRUCT or `RS_auto` is missing, the system rebuilds it directly from the validated masks. Current and legacy binary-mask naming conventions are normalized in a single pass. If both names identify the same region of interest (ROI), the current name wins so a stale duplicate cannot create a second contour. A genuine duplicate receives a progressing deterministic suffix [2, 3].

An existing `RS_auto` that is invalid, stale, or bound to another planning CT is removed from the consumer-visible path before replacement begins. This removal occurs before CT loading, segmentation selection, geometry verification, ROI addition, or saving. The removal and its reason are recorded before rebuild work starts. If rebuilding fails, automated cleanup also removes any incomplete replacement so no `RS_auto` remains available to downstream stages [3].

The function `_standard_rtstruct_sources` no longer treats simple file presence as evidence of correspondence. It offers `RS_auto` only when the file is a readable, non-empty DICOM RTSTRUCT whose referenced CT series set exactly matches the contracted planning CT series. In addition, no contracted CT, NIfTI, or segmentation dependency may be unreadable or newer than the structure set. Missing identity, conflicting identity, unreadable content, stale dependencies, and validation errors all exclude the automatic source [3].

Removal is safer than retaining or quarantining doubtful anatomical geometry in the course directory. Downstream stages already tolerate a missing best-effort automatic structure set, while an incorrect structure set can corrupt every derived ROI without revealing the substitution. Custom structure sets (`RS_custom`) retain their separate revocation rule. Production calls still require a loadable authoritative course contract [3].

Each course records the decision in `metadata/segmentation_resume.json`. The revocation entry is written immediately and includes `rejected_artifact` with the `removed` action, the `RS_auto.dcm` path, and the exact rejection reason. The same decision records whether rebuilding then succeeded or failed. Model runs are recorded only after the attempt completes. A model ineligible for quality control (QC) is marked as `skipped`, and a failed invocation is marked as `failed`, rather than either being reported as rebuilt. A reuse-only run leaves the mask manifest generation time unchanged. The audit update remains separate from mask provenance, and earlier skipped-model information is retained when rewriting a manifest [2, 3].

The direct measurement for this revision used the production mask-currentness predicate on Kopernik course 431057, course 2020-07. The course contained 117 existing masks occupying 23,201,947 bytes. Five repeated checks demonstrated a median wall-clock time of 8.25 seconds in this run. Compared with the measured 322 to 494 seconds for a model rerun, validating this complete mask set saved 313.75 to 485.75 seconds per applicable course. The denominator was one course with a complete, current mask set and missing derived output. The measurement is recorded by `analysis/resume_reuse_evidence.py` in `analysis/resume-reuse-measurement.json` [4].

This revision applies the content boundary to TotalSegmentator masks and the derived structure sets `RS_auto` and `RS_custom`. It does not claim that every stage sentinel is now safe for content-based reuse. The campaign registry still lists `.organized`, `.segmentation_done`, `.custom_models_done`, `.crop_ct_done`, `.dvh_done`, `.radiomics_done`, `.radiomics_robustness_done`, and `.qc_done`. The remaining stages still use their sentinel workflow gates. Extending them requires stage-specific output inventories and dependency identities, so that work is deferred rather than represented as complete. In particular, the NTCV robustness chain remains outside this repair. Its reported scale is 81 perturbations across 5 target ROIs, or 405 perturbed extractions per course, at roughly 0.9 hours per course [1, 5].

Resume completeness is unchanged. A conversion that never completed remains ineligible for a resume skip. A checkpoint without a required adjudication remains rejected. The existing completeness tests and the new content-reuse tests provide the focused regression boundary. The operational next step is to rerun organize so each course receives its authoritative contract. Then inspect the per-course decisions before expensive stages proceed. Reuse only positively identified current outputs. Rebuild anything missing, stale, mismatched, incomplete, or uncertain [1, 6].
